# デモ動画と説明の作り方の参考

ハッカソンのメンター、講師、他の参加者の助言と経験談のうち、この作品に使えるもの。**運営のルールではない。** ルールと運営の回答はリポジトリの外の運営情報にある。この文書は、その第5.3節と第11節（2026-11-05 版）の要点である。

## デモ動画

- 冒頭で「誰のために、何を、どう解決するか」を言い切る。審査基準のデモの項目と同じ
- 一番の見せ場を1つに決めて押す。主役は実際に動く画面で、凝った演出は冒頭と区切りに少しでよい
- 書類を点検する道具は、動きが地味で目に留まりにくい。この作品はこの型に当たる。全学生の再判定と影響人数を、図が動く場面として見せるか、その場で結果が出る見せ方にする
- 図を動かすときは、全部の図で同じデータを使い、図の種類と見せる順番を先に決める。動かす前に、各図を静止画にして読みやすさを確かめる。音楽の拍と図の切り替えを同じ設計図で合わせる
- 秒数、見せる画面、テロップ、語りを1行ずつ並べた絵コンテ表で、動画にする前に構成を直す
- 書き出したあとの修正は「0:32 の見出しを短く」「シーン3を2秒詰めて」のように、時間やシーン番号で指示する
- 要所のフレームを静止画にして確かめ、文字の重なりやはみ出しを直す。「かっこよく」ではなく、文字や画面の役割まで具体的に頼む
- 見せたいところを30秒ほどのクリップで作りためておき、最後に1本につなぐ。早めに一度、最後まで通して書き出す
- 声の語りは入れる。語りがなくてもルール上は問題ないが、評価（伝達、デモ）に少し関わる（運営の回答）

## 説明（README、概要）

- 「誰が、どんな場面で、どれくらい困っているか」と「ハッカソン後も誰がどんな場面で使い続けるか」を、そのまま言える形で書く。審査基準のインパクトの項目と同じ
- 法令、条例、公的な様式は画面に映してよい（運営の回答）。判定の根拠として条文を見せる場面に使える
- Claude で作っていないもの（語りの音声など）は、出典と合わせてそう分かるように書く（運営の回答）

## Claude Code の進め方

- 指示に締切や日程を書かず、やることの一覧で渡す。締切を書くと「期限に間に合わない」と Claude が勝手に後回しにすることがある
- 作業を止める質問は1つのファイルにまとめさせ、止まらずに進めさせる。人の判断が要るものは、作業の妨げにならない限り後回しにして一覧で報告させる
- 自分で判断しない範囲を指示に書き、それ以外は任せる。この作品では `AGENTS.md` の「守ること」がその範囲に当たる
- 判断が要るときは推奨案を出させ、別のサブエージェントに検証させてから進め、人が後で最終決定する
- Claude の作業時間の見積もりは当てにならず、予定より早く終わることが多い。浮いた時間は機能を足すより完成度の確認に回す
- 壁打ち用のセッションと実装用のセッションを並べて動かし、待ち時間を減らす
- 機能とモデルの使い分けは、理由と合わせて `docs/PROGRESS.md` に書く。例: ultracode は中断しても再開でき、作業が多いときに向く。Agent Teams はエージェント同士が双方向にやりとりし、並行して作るときに向く
