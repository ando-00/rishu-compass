**Claude Code の使い方:** 土台の作成と入力データの取り込みを任せた。入力データに仕込みの注記や実在の大学名がないことを読んで確認させた。2校の要項を読ませてルールの形式を設計させた。正解ルールの内容には触れさせず、見本は架空の値だけにした。判定エンジン、データ生成、API、画面の実装を任せ、テストを先に書かせた。`docs/AUDIT.md` の基準との差を実装で埋めさせ、画面はヘッドレスのブラウザで操作して確認させた。リポジトリの外の仕様文書と実装の差を洗い出させ、監査の指摘とあわせて直させた。T 番号のテスト用ルールは正解ルールとは別に作らせた。エンジンを90か所壊す検査を走らせ、すり抜けた7か所にテストを足させた。監査で見る範囲と回数を決めさせ、再現テストと壊す検査で現状を測らせた。指摘が直ったことは、作り直したあとのコードで確かめ直させた。正解ルールは、解釈の案を出させず、条文ごとの質問に答える形で決め、清書と根拠の検査を任せた。別のセッションと担当を分けて同時に進めさせ、壊す検査の一覧の更新とすり抜けたテストの追加を任せた。科目の時間割の規則と1行の概要を作らせ、判定の変化を前後で測らせた。回答の記録は、本物のマイグレーションを SQLite に流すテストを先に書かせ、ローカルの D1 とヘッドレスのブラウザで回答から取り消しまで確かめさせた。

**Claude Code の使い方（ルール変換）:** 構造化出力の制約は公式の文書を読ませ、拒否された理由は API を実際に呼ばせて測らせた。別のセッションと担当を分けて並行で進めさせた。正解ルールの中身は読ませずにプロンプトを書かせ、結果の数字がおかしいときは engine で正解ルールと突き合わせて原因を確かめさせた。
