**Claude Code の使い方:** 土台の作成と入力データの取り込みを任せた。入力データに仕込みの注記や実在の大学名がないことを読んで確認させた。2校の要項を読ませてルールの形式を設計させた。正解ルールの内容には触れさせず、見本は架空の値だけにした。判定エンジン、データ生成、API、画面の実装を任せ、テストを先に書かせた。`docs/AUDIT.md` の基準との差を実装で埋めさせ、画面はヘッドレスのブラウザで操作して確認させた。リポジトリの外の仕様文書と実装の差を洗い出させ、監査の指摘とあわせて直させた。T 番号のテスト用ルールは正解ルールとは別に作らせた。エンジンを90か所壊す検査を走らせ、すり抜けた7か所にテストを足させた。監査で見る範囲と回数を決めさせ、再現テストと壊す検査で現状を測らせた。指摘が直ったことは、作り直したあとのコードで確かめ直させた。正解ルールは、解釈の案を出させず、条文ごとの質問に答える形で決め、清書と根拠の検査を任せた。別のセッションと担当を分けて同時に進めさせ、壊す検査の一覧の更新とすり抜けたテストの追加を任せた。科目の時間割の規則と1行の概要を作らせ、判定の変化を前後で測らせた。回答の記録は、本物のマイグレーションを SQLite に流すテストを先に書かせ、ローカルの D1 とヘッドレスのブラウザで回答から取り消しまで確かめさせた。履修案は engine のテストを先に書かせ、実際の Claude で流した結果を読ませて、道具の呼び出しの記録から原因を突き止めさせた。

**Claude Code の使い方（ルール変換）:** 構造化出力の制約は公式の文書を読ませ、拒否された理由は API を実際に呼ばせて測らせた。別のセッションと担当を分けて並行で進めさせた。正解ルールの中身は読ませずにプロンプトを書かせ、結果の数字がおかしいときは engine で正解ルールと突き合わせて原因を確かめさせた。

**Claude Code の使い方（正解ルールの2校目）:** かもめ大学の正解ルールは、解釈の案を出させず条文ごとの選択肢で決めた。回答が値を決めるものか、質問への質問かを読み分けさせ、手引きの原文を別タブで開かせて答えた。仕様メモとの差や、未回答で止める範囲は、影響だけを示させて人が決めた。

**Claude Code の使い方（運営の情報）:** Discord の回答と提出フォームを企画フォルダの `11_運営情報`（2026-11-02 時点）にまとめさせ、ルールと記録との差を洗い出させた。公開 URL は、運営の回答をもとに人が「作らない」と決めた。審査員は API キーを持たない前提で考え、実際の変換の記録を読み込む経路を作らせた。確定の検査は通常の案と同じにして、Claude を呼ばないことをテストで固定させた。`README.md` の手順は、鍵のない新しいクローンをヘッドレスのブラウザで操作して確かめさせた。最初の確認は別のセッションのサーバーが答えていて無効だったので、ポートと PID を確かめてやり直させた。Windows のパス長で D1 の準備が止まることも、この確認で分かった。
